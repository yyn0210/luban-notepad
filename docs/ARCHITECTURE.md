# 架构

Luban Notepad 有意将文档引擎与 GUI 分离。引擎可以在无界面环境下测试，并可被
未来的其他前端复用；GUI 只负责渲染、输入和平台集成。

## Crate 划分

### `luban-core`

| 模块 | 职责 |
| --- | --- |
| `document` | 打开/保存/重新加载、未保存状态跟踪、选区、编码与换行符元数据、撤销集成；磁盘状态（未变/已变/缺失）；磁盘引擎文档的状态与无锁元数据缓存。 |
| `atomic_write` | 同目录临时文件、`flush` + `fsync`、权限保留、符号链接跟随和原子替换；失败时清理临时文件并保留原文件；测试构建可注入部分写入/ENOSPC 故障。 |
| `local_history` | 保存前快照：按规范化路径分桶、内容去重、按时间列出/读取/清空、保留天数与每文件空间上限；快照存放于配置目录 `history/`。 |
| `disk_engine` | 超大文件磁盘引擎：分块索引、块缓存、写时复制编辑日志、piece 表、全局行列换算、窗口读取、流式查找/替换、跨窗撤销、流式原子保存与重新索引、checkpoint + 操作日志崩溃恢复。 |
| `disk_engine::recovery` | 恢复目录布局、checkpoint/操作日志读写、源文件身份校验、启动扫描与过期清理。 |
| `encoding` | BOM 与统计式编码检测、解码、编码、二进制文件启发式判断。 |
| `eol` | 主要换行符检测与规范化。 |
| `undo` | 有界撤销/重做栈，支持连续输入/删除的合并。 |
| `text` | 按字符索引的行索引、行/列转换、行块选择、复制/删除行、缩进、注释、排序、大小写转换、括号匹配、预览、缩进折叠候选。 |

| `workspace` | 文件夹列表、递归在文件中查找、通配符掩码、取消、忽略规则。 |
| `language` | 扩展名/文件名→语言检测、注释语法、语言菜单列表。 |
| `settings` | JSON 设置、校验/范围限制、最近文件记录。 |
| `session` | 原子化会话持久化，包含未保存的缓冲区。 |
| `i18n` | 界面语言解析（环境变量/设置/操作系统）、引擎文案与语言显示名翻译；catalog 位于 `locales/ui.yml`。 |

## 命令与快捷键

`commands.rs` 是菜单、工具栏、快捷键帮助和命令面板的唯一标签与默认绑定来源。
每个命令有稳定的 kebab-case ID、分类、本地化 key、默认绑定和启用条件。
`Keymap::build` 将用户覆盖与默认值合并为有效绑定，并记录被覆盖命令的旧默认
键；按键处理先查有效绑定，命中的编辑类命令只在编辑器拥有焦点时执行，避免抢走
查找框/对话框的 `Ctrl+C/V/A`。被覆盖的旧默认键会被消费但不执行旧行为。

快捷键编辑器用下一条真实按键生成绑定，`validate_override` 解析、格式化并检查
冲突；冲突或无效输入不写入设置。设置中的 `keybindings` 映射在启动时丢弃未知
命令和无法解析的值。

## 编辑工具与搜索

`line_ops`、`bookmarks`、`macros` 和 `export` 保持无 GUI，便于单元测试。
行操作、列编辑和筛选都通过一次 `replace_document_text` 进入现有撤销栈；书签只
保存 1-based 行号并在文本变化时按字符级公共前后缀调整，不写入文档或撤销栈。
宏只记录命令 ID，回放走 `run_command`，因此不会绕过菜单/快捷键的启用条件。

`SearchEngine` 默认使用 Rust `regex`；用户勾选“增强正则”时改用 fancy-regex，
替换模板由共享展开器处理 `$1`、`\1`、`\U`、`\L`、`\E`。替换全部先通过
`preview_replace` 生成总数和样例，确认后重新计算并执行，避免使用过期匹配。

`app` 在文档变化后为 Python/YAML/Makefile 计算缩进折叠候选并通过
`apply_highlighter_fold_candidates` 应用；折叠动作仍由行号栏按钮完成。
`luban-app::syntax_theme` 把 two-face 内置主题和导入的 `.tmTheme` 映射到
gpui-component 的 `HighlightTheme`；导出复用同一 syntect 主题生成 HTML/RTF。

## 本地历史与日志

`HistoryStore` 在普通文本保存前读取磁盘旧内容，按规范化路径哈希分桶写入
`history/<hash>/<timestamp>-<seq>.snap`。恢复时按当前文档编码解码快照、统一为
LF 并作为一次可撤销编辑写入缓冲区，磁盘保持不变。启动和每次快照后按设置清理
过期与超限快照，最新一条不会被空间上限删除。

日志初始化在窗口创建前完成：`logs/luban.log` 追加写入，启动时超过 5 MiB 则
轮转 `.1`–`.3`；panic hook 写 `logs/crash.log`。日志目录不可写时只降级到终端。

## 文档模型

### 内部文本始终为 LF

文件可能使用 LF、CRLF 或 CR。打开时，引擎会检测主要换行符约定，将其存入
`Document::eol`，并把内存中的文本规范化为 LF。这样做有三个重要原因：

1. GPUI 编辑器基于 LF 文本工作。
2. 搜索和行索引只需处理一种明确无歧义的换行字符。
3. 保存是唯一重新引入 CRLF/CR 的地方。

`Document::save` 会先把缓冲区规范化为所选的换行符，再用所选的
`TextEncoding` 编码。保存操作会报告目标编码是否不得不替换无法表示的字符。

内容被 `looks_binary` 判定为非文本的文件是例外：应用仍会打开它（参考 Notepad++），
但改用字节可逆的编码读取（合法 UTF-8 保持 UTF-8，其余使用 Windows-1252），
保留原始换行字节，不做 LF 归一化；保存时直接回写缓冲区，不转换换行符、不裁剪
行尾空白，因此未编辑的字节保持不变。非文本文档不支持换行符转换，状态栏会显示
“非文本”标记。

### 字符索引与字节索引

GUI 和大多数文本操作使用 **字符** 索引，与 GPUI 光标位置一致。`regex`
报告的是 **字节** 偏移，因此 `search` 会按匹配顺序增量扫描字节并累计字符数，
把字节偏移换算为字符偏移。这样不需要为整篇文档建立字符边界表，Unicode 文档
（中文、日文、韩文、emoji、组合字符）仍然保持正确。

### 文本快照与字符数

`Document::text` 是编辑器内容的快照。普通文档在每次编辑器事件后通过
`set_text_from_widget` 做一次差异同步；大文件模式则由编辑器持有唯一的全文副本，
`Document` 只在保存、查找或编辑命令期间临时取回快照（`attach_text`），完成后用
`detach_text` 释放。`Document::char_count` 在打开、编辑和撤销时增量维护并缓存，
因此选区夹取和状态查询不再扫描全文。

### 撤销

引擎记录最小替换 `(start, removed, inserted)` 以及操作前后的选区。连续的输入和
退格会在很短的时间窗口内合并，且一旦涉及换行符就不再合并。历史记录有上限
（500 条）。换行符变更属于元数据变更，有意不进入文本撤销栈；它会将文档标记为
已修改，因为保存后的字节会发生变化。

> GPUI 编辑器在输入时维护自己更细粒度的撤销历史。菜单/键盘的撤销与重做会
> 分派给编辑器，产生的缓冲区再镜像回 `Document`。核心撤销栈用于无界面场景和
> 程序化变换。

## GUI 数据流

```text
EditorState (GPUI)
   │ InputEvent::Change / Focus / Blur
   ▼
LubanApp subscription ── 标记标签页 needs_sync，并通知根视图
   │
   ▼ 下一次渲染
sync_active():
   没有 needs_sync 时直接返回（空闲渲染不做全文工作）
   普通文档：读取编辑器文本、光标、选中范围（字节）
             如果粘贴引入了 CR，则规范化为 CR
             与 Document.text 进行差异比对
             Document::set_text_from_widget(...)
   大文件：  只从 Rope 换算光标与选区，更新 Document 选区
   │
   ▼
刷新查找 + 范围装饰 + 状态栏 + 标题
```

程序化变更（全部替换、排序、注释、保存时清理、重新加载）会先更新 `Document`，
然后调用 `EditorState::set_value`，最后重新选中合适的范围。编辑器的变更事件
不会造成问题，因为缓冲区内容已经一致。

### 大文件模式

文件大小达到 `Settings::large_file_threshold`（默认 100 MiB）时，标签页进入
大文件模式，语义参考 Notepad++ 的大文件限制：

- 不加载语法高亮（语言名称仍按扩展名检测）；
- 自动换行强制关闭；
- 关闭括号匹配；
- 编辑查找关键词时不自动扫描全文；按回车或点击查找按钮才读取一次快照并搜索；
- 状态栏显示“大文件模式”。

编辑、撤销/重做、选择、保存、另存为和显式查找仍然可用。大文件的未保存内容
不写入会话文件，会话只保留路径、光标和元数据，重启后从磁盘重新读取。

大文件在后台执行器上读取和解码，完成后由主线程一次性挂载编辑器；加载期间窗口
保持可交互。挂载后 `Document` 释放自己的文本副本，编辑器 Rope 是唯一全文来源。

### 超大文件磁盘引擎

`max_file_size_mb`（默认 1024 MiB，可配置 1–4096）是“整篇载入内存”的上限。
超过上限的文本文件不再被拒绝，而是由 `crates/luban-core/src/disk_engine/`
以 UltraEdit 式磁盘引擎打开：

- **分块索引**：打开时顺序扫描原文件，按完整行和字符边界切成约 1 MiB 的块；
  每块记录源字节区间、逻辑 UTF-8 偏移、起始全局行号、字符数和换行数。单行超过
  块大小时在字符边界切分，后续块标记为续行（逻辑行号不变）。索引占用只与块数
  有关，约 2.8 GB 文件约 3,000 个块，常驻内存为几百 KB。
- **逻辑文本**：所有块按文件编码解码并归一化为 LF；块边界不会切断多字节字符、
  UTF-16 码元或 CRLF。
- **piece 表与写时复制**：当前文档由若干 piece 组成，piece 指向“源块中的一段”
  或“编辑日志中的一段”。未修改内容始终从原文件读取；编辑只追加到临时编辑日志，
  不复制整份文件。
- **窗口化编辑器**：GPUI 编辑器只挂载光标附近的 2 MiB 窗口（最多 5 万行）。
  滚动接近窗口边缘、跳转、查找命中、撤销/重做或 Ctrl+Home/End 时，先同步待处理
  编辑，再在后台读取新窗口并替换编辑器文本；请求带代次，过期结果被丢弃。
  比较行宽时使用字节窗口，因此超长单行也能继续向后/向前换窗。离屏光标保存在
  `HugeFileState`，单纯滚动不会把光标错误地夹到窗口边缘。
- **跨窗撤销/重做**：历史由引擎维护，每个操作记录被替换的 piece 和被插入的
  piece；撤销/重做按全局偏移重新加载窗口并定位。历史按操作数和字节数设上限。
  撤销回到未修改状态后，相邻源块会重新合并为可直接复制的 raw piece，保存时
  逐字节还原。
- **全文查找/替换**：按 4 MiB 分块扫描逻辑文本，块间保留 1 MiB 重叠；字面量、
  正则、大小写和整词选项与普通文档一致。全部替换分批应用，取消或失败时回滚
  整组修改；`Find All` 收集最多 5,000 个匹配供结果列表跳转。
- **编码与保存**：打开时从文件头最多 64 KiB 检测编码、BOM 和换行符风格。
  保存时未修改的源块直接复制原始字节；只有编辑日志中的片段按原编码和换行风格
  重新编码。BOM 的有无按原文件保留（包括无 BOM 的 UTF-16）。
- **原子保存**：在目标目录写临时文件，`fsync` 后重命名覆盖目标；失败时删除
  临时文件并保持原文件。保存前校验源文件大小/修改时间，保存过程中再次校验；
  外部修改会要求用户选择覆盖、重新加载或取消。保存成功后用写入时记录的块偏移
  重建索引、清空编辑日志并删除恢复数据。
- **崩溃恢复**：每个发生编辑的磁盘引擎文档在配置目录 `recovery/<id>/` 下维护
  `checkpoint.json`、`edits.bin` 和 `ops.jsonl`。checkpoint 保存源文件身份、
  块索引、piece 表、光标和滚动位置；操作日志逐条记录编辑、撤销/重做和全部替换
  批次。进程崩溃或强制终止后，下次启动扫描恢复目录，校验源文件大小/修改时间后
  从最新 checkpoint 重放操作；源文件已变化或缺失时拒绝自动重放。保存、关闭或
  放弃后删除目录，超过 30 天的数据在启动时清理。
- **后台任务**：索引、窗口读取、查找、全部替换和保存都在 GPUI 后台执行器上
  运行。引擎放在 `Arc<RwLock<DiskEngine>>` 中；状态栏与关闭提示读取
  `HugeFileState` 里的原子缓存，不会因后台任务持锁而阻塞。保存和全文扫描期间
  编辑器临时只读，避免引擎内容与编辑器窗口分叉。
- **临时文件**：编辑恢复数据位于应用配置目录而非系统临时目录，正常关闭或保存
  成功时删除；遗留的旧版系统临时目录日志在启动时清理。崩溃不会留下阻塞后续
  打开的锁，也不会把未修改的源文件正文复制进恢复数据。

窗口化模型的限制：选择、复制和编辑都限于当前窗口，不能跨窗口建立选区或做整篇
块操作；磁盘引擎标签页同样关闭语法高亮、自动换行和括号匹配。

### 保存安全与外部修改

普通文档与磁盘引擎文档共享 `atomic_write::AtomicFile`：目标为符号链接时先解析
到实际文件，临时文件建在同一目录，写入后 flush、fsync、恢复原权限并原子替换；
任何一步失败都只删除临时文件。保存前 `Document::disk_status` 用大小和修改时间
判断源文件是否仍是打开时的版本，缺失也视为冲突并显示“覆盖/重新加载/取消”。

`file_watch` 用 `notify` 监视每个打开文件的父目录（非递归），500 毫秒防抖后由
应用重新读取元数据；自身保存后记录文件大小/修改时间，在短暂窗口内忽略同一路径
的事件。外部修改显示非模态“重新加载/保留”横幅，删除或重命名显示“另存为/保留”。
监视器初始化失败时应用继续工作，保存前检查仍然生效。应用空闲时也有 500 毫秒
轮询任务驱动检查，横幅不依赖鼠标或键盘事件才出现。

保存全部、全部关闭和退出把普通文档排队逐个保存；遇到外部修改会暂停整个批次并
等待用户选择覆盖或重新加载，取消会终止批次，不会在确认框背后关闭标签页或退出。

### 大文件控制器

`Settings::large_file_controller`（默认开启）控制是否在打开达到
`large_file_controller_threshold`（默认 200 MiB）的文件时自动显示右侧“大文件
控制器”。该阈值独立于 100 MiB 的大文件模式阈值。控制器也可以从“视图 >
大文件控制器”对当前文件手动打开。

- 文件不超过 `max_file_size_mb` 时默认加载整个文件；超过上限的文本文件默认用
  磁盘引擎打开整个文件（控制器标记为“磁盘引擎”），不再显示超限错误；超过上限
  的非文本文件默认只加载开头 `large_file_partial_size`（默认 200 MiB）。
- 用户可以选择整个文件、开头、结尾或中间，并通过字节输入和滑杆调整从/到/大小。
- 读取在后台分块进行，控制器显示文件大小、已打开字节、进度和临时目录可用空间；
  “停止”设置取消标记，读取在下个块边界返回 `Error::Cancelled`。
- 界面上可切换字节/KiB/MiB/GiB 显示单位；输入字段始终按字节解释。

范围读取由 `crates/luban-core/src/large_file.rs` 完成：先从文件头最多 64 KiB
检测编码，再按行边界向前/向后扩展请求区间（UTF-16 按双字节单元处理），最后解码。
如果请求的终点已经位于行首，不会再次向后扩展，因此会话恢复的区间不会逐次增长。
部分打开的实际加载长度始终不超过 `max_file_size_mb`。

部分打开的 `Document` 记录源文件总大小和实际字节区间（`PartialRange`）。它保留
编辑、撤销/重做、查找和另存为，但“保存”被禁止写回源文件：`Document::save`
返回错误，应用改为打开“另存为”；`save_as` 拒绝目标等于源路径，成功后清除
部分打开状态。部分打开的文档禁用重新加载，避免把整篇源文件读入内存。会话保存
路径和区间但不保存片段正文；重启后按区间重新读取。

### 搜索高亮

`RangeDecorationCollection` 用于两类装饰：

- **查找匹配**：填充范围，当前匹配使用更强的颜色。
- **匹配括号**：在光标所在括号对周围绘制边框。

范围使用 UTF-8 字节偏移，与装饰 API 一致。一次最多装饰 5,000 个匹配；
查找面板仍会报告其自身限制内的总数。装饰只在文档修订号、光标、查找结果或
相关设置变化时重建；大文件不绘制查找高亮与括号匹配。

### 在文件中查找

文件夹搜索在 GPUI 的后台执行器上运行，返回 `FindInFilesOutcome`。代际计数器
可防止过期结果覆盖较新的搜索。取消通过遍历器检查的 `AtomicBool` 实现。
结果保存路径、从 1 开始的行/列号、行预览、匹配文本和匹配长度，因此点击结果
可以重新打开文件并精确选中匹配文本。

### 关闭与退出状态机

关闭已修改的文档会打开确认浮层。对于多个文档，先保存有路径的文件；未命名文件
会排队，并逐个通过文件对话框询问。`SaveThen` 值告诉保存操作接下来要做什么：

- `Nothing` — 普通另存为。
- `CloseTab(id)` — 保存后关闭该标签页。
- `Exit` — 继续退出队列，然后退出。
- `CloseAll` — 继续全部关闭队列，然后关闭所有标签页。
- `NextHugeSave` — 继续磁盘引擎的“全部保存/全部关闭/退出”队列。
- `ReloadTab(id)` — 保存后重新索引并加载该磁盘引擎标签页。

窗口关闭通过 `Window::on_window_should_close` 拦截；当确认浮层打开时应用返回
`false`，并在调用 `App::quit` 之前设置 `allow_close`。

### 会话生命周期

会话会在以下时机写入：

- 启用 `autosave_session` 时，由 GPUI 定时器周期性写入；
- 窗口正常关闭时；
- 显式退出时。

会话包含每个标签页的路径、编码、换行符、语言、光标/锚点、修改标志，以及
未命名或已修改缓冲区的完整 LF 规范化文本。大文件标签页只保存元数据，不保存
完整缓冲区。恢复时会尽可能重新打开文件；如果文件已消失，则回退为未命名缓冲区，
因此文件缺失绝不会悄悄丢失未保存数据。

## 线程模型

- UI 和所有文档变更都在 GPUI 前台线程上运行。
- 达到大文件阈值的文件在后台执行器上读取、二进制检测和解码；主线程在加载期间
  保持可交互，加载完成后一次性挂载编辑器。
- 磁盘引擎的索引扫描、窗口读取、全文查找/替换和保存同样在后台执行器上运行；
  主线程通过 `Arc<RwLock<DiskEngine>>` 访问引擎，状态栏只读原子缓存。保存和
  全部替换期间编辑器临时只读。
- 在文件中查找是另一个被移到后台执行器的 CPU 密集型操作。
- 语法高亮在 GPUI Base 编辑器内部增量进行（syntect 后端）；大文件不加载高亮。
  普通文件的交互保持流畅。
- 设置/会话写入是小型同步 JSON 写入。会话采用先写入再重命名的方式，避免崩溃时
  截断上一次会话。

## 错误处理

- 核心 I/O 与解码失败返回 `luban_core::Error`；GUI 会在状态栏中显示。
- 非文本文件不再被拒绝打开：应用按字节可逆的方式读取并标记为非文本，保存时
  不重写未编辑的字节。单个文件打开失败只影响该文件，其余文件仍可继续打开。
- 超过 `Settings::max_file_size_bytes`（默认 1 GiB）的文本文件由磁盘引擎
  打开；非文本文件仍按原有部分范围路径处理。该限制可在 `settings.json` 中配置。
  大文件阈值（`large_file_threshold`，默认 100 MiB）独立于大小上限，只决定
  是否启用大文件模式。
- 无效正则表达式会在查找面板中就地提示。
- 保存失败会保持文档的已修改状态，并报告错误。

## 测试策略

- 核心行为由各模块中的单元测试覆盖。
- 与 UI 无关的路径/对话框标签逻辑有单元测试。
- Linux CI 任务会在 Xvfb 和 lavapipe 下用 `--smoke-test` 运行真实 GUI，
  验证窗口、主题、编辑器和退出流程在没有桌面会话时也能正常工作。
- 其余 UI 工作流（输入、高亮、查找面板、文件对话框、确认、会话恢复）在开发期间
  已针对虚拟显示进行交互式验证；截图位于 `docs/screenshots/`。
