# 架构

Luban Notepad 有意将文档引擎与 GUI 分离。引擎可以在无界面环境下测试，并可被
未来的其他前端复用；GUI 只负责渲染、输入和平台集成。

## Crate 划分

### `luban-core`

| 模块 | 职责 |
| --- | --- |
| `document` | 打开/保存/重新加载、未保存状态跟踪、选区、编码与换行符元数据、撤销集成。 |
| `encoding` | BOM 与统计式编码检测、解码、编码、二进制文件启发式判断。 |
| `eol` | 主要换行符检测与规范化。 |
| `undo` | 有界撤销/重做栈，支持连续输入/删除的合并。 |
| `text` | 按字符索引的行索引、行/列转换、行块选择、复制/删除行、缩进、注释、排序、大小写转换、括号匹配、预览。 |
| `search` | 字面量与正则搜索、范围、循环查找、计数、带捕获组展开的替换、单匹配替换。 |
| `workspace` | 文件夹列表、递归在文件中查找、通配符掩码、取消、忽略规则。 |
| `language` | 扩展名/文件名→语言检测、注释语法、语言菜单列表。 |
| `settings` | JSON 设置、校验/范围限制、最近文件记录。 |
| `session` | 原子化会话持久化，包含未保存的缓冲区。 |
| `i18n` | 界面语言解析（环境变量/设置/操作系统）、引擎文案与语言显示名翻译；catalog 位于 `locales/ui.yml`。 |

### `luban-app`

| 模块 | 职责 |
| --- | --- |
| `main` | 命令行参数解析、GPUI 应用/平台启动、窗口选项。 |
| `app` | 根视图、标签页、菜单、工具栏、状态栏、编辑器↔文档同步、文件编辑命令、查找/替换、在文件中查找、关闭/退出状态机、键盘处理。 |
| `dialogs` | 内置文件对话框、跳转到行、语言选择器和未保存关闭确认的状态。 |
| `find` | 查找/替换与在文件中查找面板状态。 |
| `explorer` | 文件夹树的展开/缓存。 |
| `preferences` | 首选项窗口状态。 |
| `i18n` | 界面文案翻译、locale 应用与运行时语言切换；catalog 位于 `locales/ui.yml`。 |
| `theme` | 浅色/深色 GPUI 主题应用。 |
| `util` | 路径规范化、语言标识映射、大小/路径格式化辅助函数。 |

## 文档模型

### 内部文本始终为 LF

文件可能使用 LF、CRLF 或 CR。打开时，引擎会检测主要换行符约定，将其存入
`Document::eol`，并把内存中的文本规范化为 LF。这样做有三个重要原因：

1. GPUI 编辑器基于 LF 文本工作。
2. 搜索和行索引只需处理一种明确无歧义的换行字符。
3. 保存是唯一重新引入 CRLF/CR 的地方。

`Document::save` 会先把缓冲区规范化为所选的换行符，再用所选的
`TextEncoding` 编码。保存操作会报告目标编码是否不得不替换无法表示的字符。

内容被 `looks_binary` 判定为非文本的文件是例外：应用仍会打开它（参考 Notepad++），
但改用字节可逆的编码读取（合法 UTF-8 保持 UTF-8，其余使用 Windows-1252），
保留原始换行字节，不做 LF 归一化；保存时直接回写缓冲区，不转换换行符、不裁剪
行尾空白，因此未编辑的字节保持不变。非文本文档不支持换行符转换，状态栏会显示
“非文本”标记。

### 字符索引与字节索引

GUI 和大多数文本操作使用 **字符** 索引，与 GPUI 光标位置一致。`regex`
报告的是 **字节** 偏移，因此 `search` 会按匹配顺序增量扫描字节并累计字符数，
把字节偏移换算为字符偏移。这样不需要为整篇文档建立字符边界表，Unicode 文档
（中文、日文、韩文、emoji、组合字符）仍然保持正确。

### 文本快照与字符数

`Document::text` 是编辑器内容的快照。普通文档在每次编辑器事件后通过
`set_text_from_widget` 做一次差异同步；大文件模式则由编辑器持有唯一的全文副本，
`Document` 只在保存、查找或编辑命令期间临时取回快照（`attach_text`），完成后用
`detach_text` 释放。`Document::char_count` 在打开、编辑和撤销时增量维护并缓存，
因此选区夹取和状态查询不再扫描全文。

### 撤销

引擎记录最小替换 `(start, removed, inserted)` 以及操作前后的选区。连续的输入和
退格会在很短的时间窗口内合并，且一旦涉及换行符就不再合并。历史记录有上限
（500 条）。换行符变更属于元数据变更，有意不进入文本撤销栈；它会将文档标记为
已修改，因为保存后的字节会发生变化。

> GPUI 编辑器在输入时维护自己更细粒度的撤销历史。菜单/键盘的撤销与重做会
> 分派给编辑器，产生的缓冲区再镜像回 `Document`。核心撤销栈用于无界面场景和
> 程序化变换。

## GUI 数据流

```text
EditorState (GPUI)
   │ InputEvent::Change / Focus / Blur
   ▼
LubanApp subscription ── 标记标签页 needs_sync，并通知根视图
   │
   ▼ 下一次渲染
sync_active():
   没有 needs_sync 时直接返回（空闲渲染不做全文工作）
   普通文档：读取编辑器文本、光标、选中范围（字节）
             如果粘贴引入了 CR，则规范化为 CR
             与 Document.text 进行差异比对
             Document::set_text_from_widget(...)
   大文件：  只从 Rope 换算光标与选区，更新 Document 选区
   │
   ▼
刷新查找 + 范围装饰 + 状态栏 + 标题
```

程序化变更（全部替换、排序、注释、保存时清理、重新加载）会先更新 `Document`，
然后调用 `EditorState::set_value`，最后重新选中合适的范围。编辑器的变更事件
不会造成问题，因为缓冲区内容已经一致。

### 大文件模式

文件大小达到 `Settings::large_file_threshold`（默认 100 MiB）时，标签页进入
大文件模式，语义参考 Notepad++ 的大文件限制：

- 不加载语法高亮（语言名称仍按扩展名检测）；
- 自动换行强制关闭；
- 关闭括号匹配；
- 编辑查找关键词时不自动扫描全文；按回车或点击查找按钮才读取一次快照并搜索；
- 状态栏显示“大文件模式”。

编辑、撤销/重做、选择、保存、另存为和显式查找仍然可用。大文件的未保存内容
不写入会话文件，会话只保留路径、光标和元数据，重启后从磁盘重新读取。

大文件在后台执行器上读取和解码，完成后由主线程一次性挂载编辑器；加载期间窗口
保持可交互。挂载后 `Document` 释放自己的文本副本，编辑器 Rope 是唯一全文来源。

### 搜索高亮

`RangeDecorationCollection` 用于两类装饰：

- **查找匹配**：填充范围，当前匹配使用更强的颜色。
- **匹配括号**：在光标所在括号对周围绘制边框。

范围使用 UTF-8 字节偏移，与装饰 API 一致。一次最多装饰 5,000 个匹配；
查找面板仍会报告其自身限制内的总数。装饰只在文档修订号、光标、查找结果或
相关设置变化时重建；大文件不绘制查找高亮与括号匹配。

### 在文件中查找

文件夹搜索在 GPUI 的后台执行器上运行，返回 `FindInFilesOutcome`。代际计数器
可防止过期结果覆盖较新的搜索。取消通过遍历器检查的 `AtomicBool` 实现。
结果保存路径、从 1 开始的行/列号、行预览、匹配文本和匹配长度，因此点击结果
可以重新打开文件并精确选中匹配文本。

### 关闭与退出状态机

关闭已修改的文档会打开确认浮层。对于多个文档，先保存有路径的文件；未命名文件
会排队，并逐个通过文件对话框询问。`SaveThen` 值告诉保存操作接下来要做什么：

- `Nothing` — 普通另存为。
- `CloseTab(id)` — 保存后关闭该标签页。
- `Exit` — 继续退出队列，然后退出。
- `CloseAll` — 继续全部关闭队列，然后关闭所有标签页。

窗口关闭通过 `Window::on_window_should_close` 拦截；当确认浮层打开时应用返回
`false`，并在调用 `App::quit` 之前设置 `allow_close`。

### 会话生命周期

会话会在以下时机写入：

- 启用 `autosave_session` 时，由 GPUI 定时器周期性写入；
- 窗口正常关闭时；
- 显式退出时。

会话包含每个标签页的路径、编码、换行符、语言、光标/锚点、修改标志，以及
未命名或已修改缓冲区的完整 LF 规范化文本。大文件标签页只保存元数据，不保存
完整缓冲区。恢复时会尽可能重新打开文件；如果文件已消失，则回退为未命名缓冲区，
因此文件缺失绝不会悄悄丢失未保存数据。

## 线程模型

- UI 和所有文档变更都在 GPUI 前台线程上运行。
- 达到大文件阈值的文件在后台执行器上读取、二进制检测和解码；主线程在加载期间
  保持可交互，加载完成后一次性挂载编辑器。
- 在文件中查找是另一个被移到后台执行器的 CPU 密集型操作。
- 语法高亮在 GPUI Base 编辑器内部增量进行（syntect 后端）；大文件不加载高亮。
  普通文件的交互保持流畅。
- 设置/会话写入是小型同步 JSON 写入。会话采用先写入再重命名的方式，避免崩溃时
  截断上一次会话。

## 错误处理

- 核心 I/O 与解码失败返回 `luban_core::Error`；GUI 会在状态栏中显示。
- 非文本文件不再被拒绝打开：应用按字节可逆的方式读取并标记为非文本，保存时
  不重写未编辑的字节。单个文件打开失败只影响该文件，其余文件仍可继续打开。
- 超过 `Settings::max_file_size_bytes`（默认 256 MiB）的文件会被引擎拒绝；
  该限制可在 `settings.json` 中配置。大文件阈值
  （`large_file_threshold`，默认 100 MiB）独立于大小上限，只决定是否启用
  大文件模式。
- 无效正则表达式会在查找面板中就地提示。
- 保存失败会保持文档的已修改状态，并报告错误。

## 测试策略

- 核心行为由各模块中的单元测试覆盖。
- 与 UI 无关的路径/对话框标签逻辑有单元测试。
- Linux CI 任务会在 Xvfb 和 lavapipe 下用 `--smoke-test` 运行真实 GUI，
  验证窗口、主题、编辑器和退出流程在没有桌面会话时也能正常工作。
- 其余 UI 工作流（输入、高亮、查找面板、文件对话框、确认、会话恢复）在开发期间
  已针对虚拟显示进行交互式验证；截图位于 `docs/screenshots/`。
