# 开发路线图

> 基线版本：0.14.0（2026-10-28）
>
> 本文档用于确定后续版本的优先级、范围、交付物与验收标准，作为开发排期和
> 取舍的依据。投入估算以熟悉代码库的全职开发者为基准；兼职或首次接触
> 插件沙箱会明显更长。代码引用基于 0.13.0，重构后以符号为准。

## 0. 结论

Luban Notepad 0.13 不是“功能少”，而是**能力结构偏科**：超大文件磁盘引擎是
明显领先的护城河，核心文本工作流也完整；但数据安全、编辑深度、工作区/导航、
扩展生态这四块，与主流编辑器的默认预期还有明显距离。智能化（LSP、补全、
诊断等）不做，属于定位取舍。

后续策略分三条线：

1. **防守**：补齐 Notepad++ 用户的日常编辑能力，让目标用户能无痛切换。
2. **进攻**：继续扩大超大文件优势，做主流编辑器不愿认真做的“大文本工具”。
3. **未来**：先用命令系统统一菜单/快捷键/宏，再建立插件生态。

**Luban 的定位是轻量级文本编辑器**：不追 IDE 化，不把 LSP、智能补全、调试器
等能力放进核心和版本路线图，优先保证启动快、界面简单、核心编辑可靠和超大
文件领先。

**如果只做三件事：**

1. 数据安全包：原子保存 + 外部修改保护 + 崩溃恢复。
2. 命令注册表 + 命令面板/快速打开 + 可自定义快捷键。
3. 折叠 + 多光标 + 列编辑 + 书签 + 宏。

这三件事完成后，Luban 才算跨过“Notepad++ 替代品”的门槛；之后再做插件生态
才有稳固的地基。

## 1. 现状画像

### 1.1 优势

- **核心工作流完整**：标签页、保存/另存/全部保存、重新加载、最近文件、
  会话恢复、编码与换行符、约 200 种语言高亮、查找/替换、在文件中查找、
  内置文件对话框、界面本地化、三平台打包。
- **超大文件领先**：100 MB 进入大文件模式；超过 `max_file_size_mb`
  （默认 1 GiB）的文本文件走磁盘引擎，支持窗口化编辑、跨窗撤销/重做、
  全文流式查找/替换、原子保存、文件全局滚动条和范围视图；约 2.8 GB 文件
  的进程内存增量约 24 MB。
- **跨平台一致**：Rust + GPUI，无 GTK/Qt/Electron/WebView 依赖；
  Linux/Windows/macOS 使用同一套界面和文件对话框。
- **工程基础**：约 28k 行 Rust；264 个单元测试（磁盘引擎 44 个）；
  Linux/Windows/macOS CI 构建，Linux 有 Xvfb + lavapipe GUI smoke test；
  Linux `.tar.gz`/`.deb`、Windows 安装版/便携版、macOS `.app`/`.zip` 打包。

### 1.2 短板

- **数据安全**：普通文档直接覆盖写；普通文档保存前不检查外部修改；
  没有实时文件监视；磁盘引擎标签页崩溃后未保存编辑丢失。
- **编辑深度**：折叠、多光标、列选择有引擎基础但未产品化；没有书签、
  宏、代码片段。
- **工作区/导航**：单文件夹、只读文件树；没有命令面板、快速打开、
  多窗口、分屏、项目/多根工作区。
- **扩展**：没有插件 API、脚本、用户自定义语言；LSP/智能补全等 IDE
  能力不列入路线图，属于轻量级定位的取舍。
- **分发/信任**：Windows 未签名、macOS 仅 ad-hoc 签名未公证；
  没有自动更新和包管理器集成。

## 2. 与主流编辑器的差距

`docs/FEATURES.md` 已经给出“是/部分/否”的 Notepad++ 对照。这里关注的是
**主流编辑器已经成为默认预期、而 Luban 还没有**的能力。

### 2.1 差距矩阵

| 能力域 | 当前状态 | 主流基准 | 差距性质 | 优先级 |
| --- | --- | --- | --- | --- |
| 数据安全 | 普通保存非原子；外部修改只在磁盘引擎保存时检测；磁盘引擎无崩溃恢复 | Notepad++/VS Code 有备份、文件监视、热退出/本地历史 | 信任问题，最优先 | P0 |
| 超大文件 | 可编辑磁盘引擎、流式查找/保存、全局滚动条 | EmEditor 还有行筛选、CSV 模式、临时文件、大文件高亮 | 领先，但工具化不足 | P0/P1 |
| 编辑深度 | 折叠/多光标/列选择有引擎基础；无书签/宏 | 折叠、多光标、列编辑、书签、宏是默认能力 | 日常效率 | P1 |
| 搜索 | 字面量/正则/选区/全文件/文件夹 | PCRE 前后瞻/反向引用、搜索历史、打开文档搜索、替换预览 | 功能深度 | P1 |
| 导航/工作区 | 单文件夹只读树、标签页 | 命令面板、快速打开、文件树操作、多窗口、分屏、项目 | 结构性缺口 | P1/P2 |
| 智能 | 不做补全/LSP/片段 | LSP 是代码编辑器标配，但属于 IDE 方向 | 定位取舍：轻量文本编辑器不追 IDE 化 | 不做 |
| 个性化 | 明暗主题、少量首选项 | 语法主题、快捷键自定义、每语言设置 | 体验 | P1/P2 |
| 扩展性 | 无插件/脚本/UDL | Notepad++/VS Code/Sublime 的核心生态 | 生态 | P3 |
| 分发 | GitHub Release + 三平台包 | 签名/公证、自动更新、包管理器、arm64 | 采用门槛 | P1/P2 |

### 2.2 最影响用户去留的 10 个问题

1. **普通文档保存不是原子写**：`save_to_path` 直接 `File::create`，
   崩溃或磁盘满可能把文件截断（`crates/luban-core/src/document.rs:927`）。
2. **普通文档保存不检查外部修改**：`changed_on_disk` 已存在，但只在磁盘
   引擎保存流程中使用；普通文档可能静默覆盖别人的改动
   （`crates/luban-app/src/app.rs:4586` 对比 `app.rs:4019`）。
3. **没有实时文件监视**：git 切换分支、其他编辑器保存后，只能手动
   “从磁盘重新加载”。
4. **磁盘引擎标签页崩溃丢编辑**：会话只保存路径和元数据，不保存磁盘引擎的
   未保存修改。
5. **没有命令面板/快速打开**：`Ctrl+Shift+P`、`Ctrl+P` 缺失，键盘用户效率
   明显低于 VS Code/Sublime。
6. **文件树只能看不能改**：`explorer.rs` 只有展开和打开，没有新建/重命名/
   删除/刷新/右键菜单。
7. **折叠/多光标/列编辑没有产品化**：引擎层已有折叠图标、多光标快捷键
   （Ctrl+Alt+↑/↓）和 Alt+拖选，但应用没有菜单、帮助文档和状态提示；
   `Ctrl+D` 还是“复制行”，与 VS Code 用户的“选中下一个相同项”习惯冲突。
8. **正则能力不完整**：使用 Rust `regex`，不支持前后瞻、反向引用、`\K`
   等，复杂替换做不了。
9. **没有分屏/多窗口/标签组**：单窗口单视图，跨文件对照编辑不便。
10. **安装包未签名/未公证、无自动更新/包管理器**：Windows SmartScreen 和
    macOS Gatekeeper 会形成首装摩擦；用户也很难及时升级。

### 2.3 根因分析

1. **命令层缺失，`app.rs` 已成瓶颈。** 10,311 行的 `app.rs` 里，菜单项、
   快捷键、帮助表各自硬编码（菜单构造从 `app.rs:6894` 开始）。没有统一的
   命令 ID，就无法低成本做命令面板、快捷键自定义、宏录制和插件注册。
   这是最高杠杆的架构改造。
2. **三种文档模式导致功能重复实现。** 普通文档走编辑器↔文档 diff 同步；
   大文件由编辑器持有全文；磁盘引擎是窗口化 piece 表。同一件事（查找、
   替换、保存、选区、撤销）要在三条路径上分别处理，功能容易漂移。
   需要一个统一的“编辑器能力适配层”。
3. **深度编辑能力受上游编辑器组件限制。** gpui-base 0.8 已经有折叠、
   多光标、列选择等能力，但应用只接了很小一部分。更深的能力要么
   向上游贡献，要么在适配层封装，必要时固定版本/fork。
4. **单窗口、单视图架构。** 分屏、多窗口、标签组不是加一个按钮，而是要先
   拆分应用状态（每窗口/每视图的文档集合、会话、命令目标）。
5. **syntect 是行级正则高亮，没有语法树。** 折叠只能按大括号；
   Python/YAML 这类缩进语言没有折叠；函数列表/大纲只能靠正则启发式。
   tree-sitter 是可选项，但不建议为了折叠整体替换高亮。
6. **搜索后端选择了安全但功能受限的 Rust regex。** 需要增加一个可选的
   PCRE 兼容模式，而不是替换默认引擎。

### 3.2 0.14 — 可信赖（P0，先做）

**目标：让用户敢把重要文件交给它。**

#### 交付物

- [x] **普通文档原子保存**：同目录临时文件 → `fsync` → 原子重命名；
      保留权限；Windows 使用 `ReplaceFile`/`MoveFileEx` 语义；失败时保留
      原文件；符号链接写入实际目标并保留链接。（data-safety change 已实现；
      `.bak` 备份和保存前可用空间检查仍待补。）
- [x] **故障注入测试**：模拟写入中断、磁盘满、权限不足，验证原文件不丢、
      不出现半截文件。（已覆盖权限不足、保存失败、部分写入和 ENOSPC 注入。）
- [x] **普通文档外部修改保护**：保存前检查磁盘状态，弹出
      “覆盖/重新加载/取消”；与磁盘引擎共用一致的用户选项。
- [x] **实时文件监视**：引入 `notify` 做防抖监视；外部变化时显示非模态
      提示条，支持 Reload/Keep；忽略自身保存触发的事件；处理重命名/删除。
- [x] **磁盘引擎崩溃恢复**：checkpoint + 追加操作日志写入配置目录；启动时
      检测恢复项并提示恢复；源文件变化或缺失时安全拒绝；保存/关闭/放弃后清理。
- [x] **本地历史**：普通文档按时间或保存前生成快照，支持浏览和恢复；
      设置保留期限和空间上限。
- [x] **可诊断**：日志写文件并轮转；panic hook 写崩溃日志；帮助菜单加
      “打开日志目录”。
- [x] **命令注册表**：ID、标签、分类、默认快捷键、启用条件、执行函数。
- [x] **菜单/工具栏/快捷键帮助/命令面板统一从注册表生成**；设置里保存
      快捷键覆盖。
- [x] **命令面板（Ctrl+Shift+P）与快速打开（Ctrl+P）**：复用
      gpui-component 的 `Command`/`CommandState`。
- [x] **标签页操作**：右键菜单、拖拽重排、关闭其他/右侧、复制路径、
      在文件管理器中显示、恢复关闭的标签页（Ctrl+Shift+T）。
- [x] **状态栏补充**：词数、文件大小、缩进模式、只读标记。
- [x] **系统明暗主题跟随、全屏模式。**

#### 验收

- `kill -9` 或模拟断电时，不会留下损坏文件；未保存内容可恢复。
- 外部修改后保存一定提示，不会静默覆盖。
- 所有菜单命令都能在命令面板中找到；快捷键可自定义且冲突可检测。
- 新增数据安全与命令层测试，CI 全绿。

### 3.3 0.15 — Notepad++ 编辑对齐（P1）

**目标：Notepad++ 用户日常操作不缺项。**

#### 交付物

- [x] **折叠产品化**：行号栏折叠按钮；Python/YAML/Makefile 缩进折叠候选；菜单“展开当前行/展开全部”。程序化“折叠”命令受 gpui-base 公开 API 限制，未提供键盘折叠。
- [x] **多光标/列编辑**：`Ctrl+Alt+↑/↓`、Alt+点击加光标、选中下一个/全部相同项；列编辑器（文本/递增数字、步长、补零）；列选择复制/粘贴。
- [x] **解决 Ctrl+D 冲突**：保留 Notepad++ 的“复制行”，把“选中下一个相同项”放到 `Ctrl+Shift+D`。
- [x] **行操作**：上移/下移、合并行、拆分行、删除重复行/空行、文本/数值/按列排序、忽略大小写、行筛选。
- [x] **书签/标记**：切换/上一个/下一个/清除、剪切/复制/删除书签行；查找全部可标记；书签随会话恢复。
- [x] **搜索增强**：可选 fancy-regex（前后瞻、反向引用）；替换语法兼容 `\1`、`\U`、`\L`、`\E`；搜索历史；在打开文档中查找；替换预览；结果上限提高到 20,000。
- [x] **宏**：命令级录制/回放/命名保存/删除/快捷键分配；不录制原始按键。
- [ ] **分屏**：水平/垂直分屏、把标签移动到另一视图、各自独立滚动/光标。
      （按 4.2 的取舍顺延到 0.16。）
- [x] **主题与语言**：语法配色主题选择、`.tmTheme` 导入、每语言缩进/换行设置。
      `.sublime-syntax` 用户语言与 1.0 的 UDL 包一并实现。
- [x] **导出**：HTML/RTF；跨平台打印/PDF 仍后置。

#### 验收

- 整理一份“Notepad++ 日常操作 Top 20”清单，逐项可通过。
- 折叠、多光标、列编辑、书签、宏都有菜单和帮助文档；折叠通过行号栏按钮操作，
  多光标/列编辑/书签/宏提供默认快捷键。
- `docs/FEATURES.md` 更新，不再出现“已知但未产品化”的核心编辑项。

### 3.5 1.0 — 扩展性与生态（P3）

**目标：让第三方能在不改核心的情况下扩展编辑器。**

#### 交付物

- [ ] **插件模型**：先定义贡献点（命令、菜单、快捷键、主题、语言/语法、
      片段、面板、状态栏项、设置），再选运行时。
- [ ] **运行时建议**：Lua（mlua）做脚本/宏，WASM（wasmtime）做沙箱插件；
      不暴露不稳定的 Rust ABI。
- [ ] **插件清单、权限、版本兼容、安全模式**（禁用所有插件启动）。
- [ ] **插件管理器**：zip/Git/本地目录安装、启用/禁用、更新、依赖检查。
- [ ] **首批官方插件**：文件比较/差异、JSON/XML 格式化、Markdown 预览、
      CSV 模式。
- [ ] **UDL/主题/片段包**：`.sublime-syntax`、`.tmTheme`、snippet 包格式；
      用户包目录。
- [ ] **CLI 自动化**：`--goto file:line:col`、`--wait`、`--new-window`、
      `--diff`、stdin 过滤、`--command`。
- [ ] **分发**：Windows Authenticode、macOS Developer ID + 公证、自动更新

## 4. 优先级与取舍

### 4.1 现在就应该做

1. 数据安全包（原子保存、外部修改、崩溃恢复、本地历史、日志）。
2. 命令注册表 + 命令面板/快速打开 + 可自定义快捷键。
3. 折叠/多光标/列编辑/书签/宏这组 Notepad++ 日常能力。

### 4.2 可以往后放

- 分屏、多窗口、文档地图、全库搜索：价值高，但依赖状态架构调整，放在
  0.16。
- 插件生态：1.0 的目标，不要在 0.14 就开始设计 ABI。

### 4.3 明确不做或晚做

- **不要做完整 IDE**：LSP/智能补全、调试器、终端、Git UI、远程开发不进
  核心，也不列入版本路线图；确有需要时由第三方插件提供，不占核心排期。
- **不要现在追 AI**：等插件 API 就绪后以插件形式提供，避免核心绑定某个
  模型/供应商。
- **不要整体重写编辑器**：优先把 gpui-base 已有能力接出来；不够就向上游
  贡献或做适配层，别 fork 成长期维护负担。
- **打印/拼写检查/原生文件对话框**：打印跨平台成本高、频率低，先用
  HTML/RTF 导出；拼写检查对代码编辑器优先级低；内置对话框是刻意选择，
  补“最近位置/收藏/搜索”比换原生更划算。
- **不要为了大文件继续堆功能而忽视普通文件体验**：大多数用户 99% 的时间
  在普通文件上。

## 7. 风险与依赖

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 上游编辑器 API 变化 | gpui-kit/gpui-base 升级可能破坏折叠/多光标等编辑器能力 | 固定版本、适配层封装、必要时向上游贡献 |
| 三种文档模式漂移 | 普通/大文件/磁盘引擎功能重复实现 | 先做能力适配层，新增功能必须覆盖三条路径或明确降级 |
| 插件安全 | 第三方插件可能访问文件/网络 | WASM 沙箱、权限声明、签名/审核、安全模式 |
| 平台测试不足 | Wayland、macOS 实际交互覆盖有限 | 手工测试矩阵 + 关键流程 UI 自动化 |
| 打印成本 | 跨平台打印 API 复杂 | 先 HTML/RTF 导出，打印后置 |
| `app.rs` 过大 | 10k 行单文件，改动冲突和回归风险高 | 0.14 起按命令/标签/菜单/视图/状态拆分 |

## 8. 维护方式

- 本文档是活文档：每个版本发布前更新“交付物”复选框和“验收”结果。
- 新增需求先判断属于哪条线（防守/进攻/未来），再决定是否进入当前版本。
- 每个版本结束时更新 `docs/FEATURES.md`，保持对外功能声明与实际一致。
- 如果某项估算明显偏离，调整范围而不是降低验收标准；数据安全和性能
  指标不降级。
